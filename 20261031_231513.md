- `Phase[n] = (Acc[n] + Offset) mod 1`

The additions use `olo_fix_add` with wrap. This makes the first output after a reset equal to `sin/cos(Offset)`; the alternative is `Offset + Step`. Is that what you want?

## Assistant <sup>10/31/2026, 11:49:39 PM</sup>

I added an optional PRBS dither to the Python model only. It gives little SFDR gain at typical frequencies and costs about 3 dB SNR; the clear win is only for steps close to a simple fraction of Fs, like 1/3.

**What I added**
- **Dither option:** `olo_fix_dds(..., dither=False)` in [olo_fix_dds.py](src/fix/python/olo_fix/olo_fix_dds.py). When on, the dither is added to the full-resolution phase (wrapping) before it is rounded for `olo_fix_sin`.
- **Dither format:** `(1, -(K-1), M)`, which spans exactly ±2 LSB of the rounded phase. M is the full phase resolution and K the rounded one. For a 32-bit phase and 16-bit output this is a 14-bit PRBS symbol per sample.
- **PRBS source:** a bit-true Python port of `olo_base_prbs` (PRBS23, seed all ones). A new unit test checks it against the reference sequence in `olo_base_prbs4_tb` for all five symbol widths that testbench uses, and it matches. The port is a private class inside `olo_fix_dds.py` for now.
- **Tests:** 16 tests pass and coverage is still 100%. The VHDL is unchanged.

**What this means**
- **Odd frequencies:** the gain is small, 0 to 2 dB, up to about 5 dB for 10-bit output. Without dither, `olo_fix_sin` already stays below 1 LSB of error with the phase rounded to N+4 bits, so phase truncation spurs aren't the limit. The remaining spurs come from amplitude quantization and the approximation. A ±2 LSB phase dither only moves the amplitude by about 0.8 LSB near zero crossings, and much less near the peaks.
- **Steps near a simple fraction of Fs:** this is the clear win, +3 to +17 dB. The quantization error repeats with a short period there, which piles the energy into a few large spurs, and the dither spreads them out.
- **Cost:** the noise floor rises by about 3 dB in every case. In hardware it would also add a PRBS, one adder and probably one pipeline stage.

**My recommendation:** it's worth adding as an optional generic, defaulting to off, documented as something for steps that are simple fractions of Fs. It's not worth turning on by default.

If you want to look further first, I could try larger amplitudes (±4 or ±8 LSB). They should spread the amplitude spurs better, at a larger SNR cost. If you decide to adopt dithering, the PRBS port should probably become a standalone shared model rather than living inside `olo_fix_dds.py`.

## Assistant <sup>10/31/2026, 11:52:58 PM</sup>

**Short answer:** the best phase dither is uniform and exactly **1 LSB wide** (of the rounded phase), not ±2 LSB. But in `olo_fix_dds` no phase dither helps much, because phase truncation doesn't cause the spurs that limit it.

**What the literature says** (Flanagan & Zimmerman, the NASA report; it is a scanned PDF and I read all of it):
- **First-order dither:** a uniform dither exactly 1 LSB wide (the discarded phase bits filled with random bits) makes the truncation error independent of the signal. Phase spurs then fall at about 12 dB per phase bit instead of 6.
- **Higher order:** adding M independent 1-LSB variates gives 6(M+1) dB per bit. M=2 is a triangular dither over ±1 LSB and gives 18 dB per bit. Noise power grows linearly with M.
- **Width matters:** the dither width has to be an exact multiple of the LSB. Going wider than 1 LSB only adds noise. My ±2 LSB uniform dither is 4 LSB wide, so it has 16 times the noise power of the 1-LSB version and no better spur suppression.
- **Amplitude spurs:** phase dither doesn't touch these. They need their own 1-LSB amplitude dither before the output rounding.

**My measurements** (bit-true `olo_fix_sin`, SFDR / SNR in dB, odd step 0.0123):

| Configuration | none | rect 1 LSB | tri ±1 LSB | rect ±2 LSB |
|---|---|---|---|---|
| Ideal sine, K=10 phase bits | 59.9 / 55.0 | **83.3 / 52.0** | 80.9 / 50.3 | 73.6 / 42.7 |
| Ideal sine, K=14 phase bits | 84.1 / 79.1 | **106.7 / 76.1** | 105.6 / 74.4 | 97.5 / 66.8 |
| `olo_fix_dds` 10-bit (K=14) | 76.8 / 67.0 | 78.8 / 66.8 | 80.8 / 66.4 | 81.4 / 64.3 |
| `olo_fix_dds` 16-bit (K=20) | 118.3 / 103.5 | 118.5 / 103.3 | 118.9 / 103.0 | 119.1 / 100.3 |

- **Isolating phase spurs:** the "ideal sine" rows use a floating-point sine, so only phase effects remain. There, 1-LSB dither gains about 23 dB of SFDR for a 3 dB SNR loss, and is the best choice.
  - The dithered SFDR in those rows is limited by the random peaks of the noise floor in a 32768-point FFT, not by real spurs, so the true spurs are lower still.
  - That same noise limit is why the triangular dither looks slightly worse here despite its better theoretical spur suppression.
- **Real configurations:** with the phase already rounded to K = N+4 bits, phase spurs sit about 24 dB below the spurs from amplitude quantization and the linear approximation. Phase dither therefore changes SFDR by only 0 to 1 dB at 16 bits.
- **Steps near 1/3 of Fs:** the gains there (+3 to +17 dB) mostly come from the ±2 LSB dither also slightly scattering the amplitude error. That works only by accident and costs 3 to 6 dB of SNR.

**My recommendation:**
1. **Don't add phase dither to the VHDL.** For this entity it costs a PRBS, an adder and SNR for at most about 1 dB of SFDR at typical frequencies.
2. **For real spur reduction, use amplitude dither inside `olo_fix_sin`.** It would go before its output rounding, so spurs are set by the wider internal word length rather than the output width, at the cost of about 3 dB SNR. That changes `olo_fix_sin`, not `olo_fix_dds`.
3. **Where phase dither would pay off:** reducing K below N+4 to shrink the multiplier inside `olo_fix_sin`. With 1-LSB dither, K=10 already reaches the 10-bit amplitude spur level. The table size is fixed by the output format, though, so the saving is small.

The Python model still has the ±2 LSB option. Should I switch it to the 1-LSB version, or remove the dither option entirely?

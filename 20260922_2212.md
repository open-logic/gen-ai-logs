No, the font size of the name plays no role - you can change it freely.

The script reads the name with `"".join(cells[0].itertext()).strip()` in [ExportFormulas.py:78](doc/fix/approx/ExportFormulas.py#L78), which collects only the character data of the cell. The same is true of the **formula's** font size, which is the one that could plausibly have bitten you. `render()` discards the embedded object entirely except for its StarMath annotation string, writes a fresh MathML file, and lets LibreOffice render it at default settings; the output scale comes solely from `DPI = 209` in the script. Evidence: `Object 2` carries `BaseFontHeight = 12` in its `settings.xml`, `Object 4` has no `settings.xml` at all, and since both hold the same StarMath their exports are pixel-identical.

Two things that *do* matter:

- The name's **text content** - it is the output file name verbatim, so stray spaces inside it (leading/trailing are stripped) or a missing `.png` carry through.
- `size` commands **inside** the StarMath itself (`size 20 {...}`, `size*2 {...}`) - those are part of the annotation and are rendered.

What gets ignored besides styling: the `svg:width`/`svg:height` on the frame, the table and cell styles, and the object's `settings.xml`.
